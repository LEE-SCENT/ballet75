# 발레75 (ballet75) — 회원 수강관리 웹

PRD 기반 모바일 우선 프로토타입. 빌드 도구·의존성 없이 동작하는 정적 웹앱(ES Modules + 순수 CSS)입니다.

## 실행

```bash
python3 devserver.py
```

`http://localhost:4175` 접속. (Claude Code에서는 `.claude/launch.json`의 `ballet75` 구성으로 실행)

ES Modules를 사용하므로 `file://`로 직접 열면 동작하지 않습니다. 반드시 로컬 서버로 실행하세요.
`devserver.py`는 `Cache-Control: no-store`를 붙입니다 — 브라우저가 모듈을 캐시하면 코드를 고쳐도 이전 화면이 계속 뜹니다.

## 시간표

`data.js`의 `WEEK_TEMPLATE`은 발레75 실제 주간 시간표다 (월~일, 베이직/레벨1~3/준비반/센터집중반/토슈즈1/작품반/발레스트레칭).

- 모든 수업 **80분**. 예외만 `dur`로 지정 — 발레스트레칭 60분, 일요일 토슈즈1 30분
- 시간표에 `14, 28일`로 적힌 토요일 13:40 레벨2는 **격주**다. `weeks: [2, 4]`(그 요일의 2·4번째 주차)로 구현해 어떤 달에도 맞게 생성된다
- 발레스트레칭은 시간표에 홀 표기가 없어 강사만 노출한다 (`placeLine()`)
- 강사: 경리T · 소정T · 서연T · 현T · 혜란T · 지민T · 규리T / 홀: A홀 · B홀
- 개인레슨은 시간표 밖 단건 예약으로 따로 둔다
- **개강·종강** — 4주(28일) 운영이되 개강일이 달마다 달라서, 규칙이 아니라 월별 표(`TERMS`)로 관리한다. 기간 밖에는 수업이 생성되지 않아 캘린더에서도 비활성이다. **8월은 `8/4~8/31`로 확정**, 7·9월은 임시값
- **레벨 안내** — `LEVEL_GUIDE`. 수강신청 화면의 `레벨 안내` 버튼과 수업 상세에 노출된다

## 수강료 · 보강 · 쿠폰

**정규반은 반 종류가 아니라 주 N회로 월정액이 정해진다.** (4주 28일 기준)

| 주 N회 | 월 수강료 | 할인 | 회당 | 취소·보강 |
|---|---|---|---|---|
| 주 1회 | 132,000원 | – | 33,000원 | 0회 |
| 주 2회 | 211,000원 | 20% | 26,400원 | 2회 |
| 주 3회 | 277,000원 | 30% | 23,100원 | 2회 |
| 주 4회 | 316,000원 | 40% | 19,800원 | 3회 |

**취소와 보강**은 한 쌍이다. 주 N회 수강권은 한 달에 정해진 횟수만큼 취소할 수 있고, **취소한 횟수만큼** 보강으로 신청할 수 있다.
`보강 가능 = min(그 달 취소 건수, 월 한도) − 사용분` (`state.js`의 `makeupAvailable()`)


- 보강은 **마감되지 않은 반**에만, **수업 하루 전날 자정까지** 신청할 수 있다
- **수업 취소도 하루 전날 자정까지** — 당일 취소는 불가 (`canCancel()`)

**쿠폰**은 정규와 별개로 구매하는 회차권이다. PRD §2.2가 남겨둔 "상품형 쿠폰"이 실제로 존재하는 것이 확인되어, 보강과 분리된 도메인으로 구현했다.

**일반 쿠폰** — 수량별 묶음가 (`COUPON_PRICE.general.bundles`)

| 수량 | 1 | 2 | 3 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| 금액 | 33,000 | 51,000 | 84,000 | 133,000 | 166,000 | 181,000 | 214,000 | 247,000 | 280,000 |
| 회당 | 33,000 | 25,500 | 28,000 | 26,600 | 27,667 | 25,857 | 26,750 | 27,444 | 28,000 |

가격 구조는 **수량 × 33,000원 − 구간별 정액 할인**이다.

| 수량 구간 | 할인액 |
|---|---|
| 1개 | – |
| 2~4개 | 15,000원 |
| 5~6개 | 32,000원 |
| 7~10개 | 50,000원 |

구간 안에서 1개를 더하면 정가(33,000원)가 그대로 붙으므로, 회당 단가는 각 구간의 첫 수량(2·5·7개)에서 가장 싸고 이후 다시 올라간다. 회당 단가가 단조 감소하지 않는 것은 이 구조의 결과다.

**발레스트레칭 쿠폰** — 1개 25,000원, 묶음 할인 없이 수량 × 단가.

> 확인이 필요한 항목(4개 가격, 5개 가격 불일치 등)은 별도 정책 문서에 정리돼 있습니다.

- 유효기간 등록일 기준 30일, 만료 시 7일 연장 1회 (30,000원)
- **반마다 쿠폰 자리는 2석** (`COUPON_SEATS`) — 정규 정원과 별도로 관리한다
- 당일 취소 불가, 결석 시 차감. 기한 내 취소하면 1회 복구
- **스트레칭 쿠폰**은 발레스트레칭 전용으로 종류를 분리해 두었고, **가격표는 확인 중**이다

**개인레슨** 60분 80,000원 / 80분 100,000원.

## 정규 신청 모델 — 요일(반) 단위

정규는 날짜를 하나씩 고르는 게 아니라 **요일 + 시간의 반**을 담는다. 반을 담으면 그 달의 남은 회차가 함께 따라온다.

```
주 몇 회 선택  →  반(요일) 담기  →  회차·금액 자동 계산  →  담은 수업  →  신청 확인  →  완료
```

- **시간표 뷰** — 요일별로 열리는 반 목록. 카드에 `8월 3회 · 17·24·31일`과 월 수강료 표시
- **캘린더 뷰** — 날짜를 누르면 그 요일 전체(예: 화 → 1·8·15·22·29)가 한 번에 잡힌다. 요일 헤더(월화수…)는 라벨일 뿐 선택 대상이 아니다
- 요일은 **주 N회만큼 동시에** 고를 수 있다 (주 2회 → 화·목 둘 다 켜짐). 초과하면 토스트로 안내
- 한 요일에는 반 하나. 같은 요일의 다른 반을 누르면 교체된다
- 캘린더 강조는 2단계 — 고른 요일의 날짜(연한 톤) → 담은 반의 실제 회차(진한 톤)
- 수강료는 담은 반과 무관하게 **주 N회 월정액**으로 계산된다
- 이미 지난 회차는 제외되므로 월 중간 신청이면 `8월 3회`처럼 남은 회차만 계산된다
- 월 선택은 **이번 달 + 다음 달**만 노출한다. 지난달은 신청도 보강도 불가라 보여줄 이유가 없다
- 월을 바꾸면 회차가 달라지므로 담은 반을 비운다 (8·9월 합산 결제 없음)
- 정원은 **반(요일+시간+월) 단위**라 같은 반의 모든 회차가 잔여석을 공유한다

**보강과 쿠폰은 하나의 화면을 공유한다.** 둘 다 "그 날 그 수업 하나"를 신청하는 일이고, 회원 입장에서는 수업을 먼저 고르고 무엇으로 낼지는 나중에 정하는 게 자연스럽다.

```
수업 신청 → 수업 고르기 → 무엇으로 신청할지 고르기(보강 / 쿠폰) → 완료
```

- 목록에는 **어떤 수단으로든 신청 가능한** 수업이 모두 나오고, 카드에 `보강 · 쿠폰으로 신청 가능`처럼 쓸 수 있는 수단을 적는다
- 확인 화면에서 수단을 고른다. 못 쓰는 수단은 이유와 함께 비활성 (`남은 보강 없음`, `쿠폰 자리 마감`, `당일 신청 불가`)
- 대상이 완전히 같지는 않다 — 보강은 **정규 정원**, 쿠폰은 **반마다 2석**을 본다. 그래서 쿠폰만 되는 수업, 보강만 되는 수업이 생긴다
- 날짜는 **주간/월간 캘린더**에서 고른다. 신청 가능한 날에만 점이 찍히고, 고른 날의 수업이 아래에 나온다
- 발레스트레칭은 스트레칭 쿠폰만 후보에 오른다
- 관련 코드: `bookingMethods()` / `submitBooking()`

관련 코드: `state.js`의 `regularSlots()` / `slotStatus()` / `selection()` / `toggleSlot()`.

## 수강신청 오픈 (운영 정책)

다음달 정규반 신청은 **현재달**에 미리 한다.

| 대상 | 신청 기간 |
|---|---|
| 기존 회원 | 현재달 **20일 ~ 말일** |
| 신규 회원 | 현재달 **22일 ~ 말일** |

오픈일에 마감되는 게 아니라 말일까지 열려 있고, 그 사이에는 **자리가 남은 반**만 신청할 수 있다.

기존 회원의 기준은 회원가입 여부가 아니라 **지난달에 수업을 들었는지**다 (`state.js`의 `isReturningMember()`).

- 오픈 전에는 **미리보기만** — 반 목록은 보이되 카드가 `오픈 예정` 상태로 잠기고, `주 N회` 선택도 숨긴다
- 홈 `확인이 필요해요`에 D-7부터 오픈 안내가, 오픈 후에는 신청 CTA가 뜬다
- 진행 중인 달의 **중도 등록**(9월에 9월 반 신청)은 정책 확정 전이라 기본은 닫아 뒀다.
  `data.js`의 `ALLOW_MID_MONTH_ENROLLMENT`, 또는 마이 > 프로토타입 상태 보기의 `이번 달도 신청 허용` 스위치로 켤 수 있다.
  닫혀 있을 때 이번 달 탭은 시간표 열람 + 보강 진입 용도로 남는다
- 오픈일 상수: `data.js`의 `ENROLLMENT_OPEN_DAY = { returning: 20, new: 22 }`

"지난달"의 기준 달은 확인이 필요하다 (정책 문서 2-7)

## 장바구니

별도 장바구니 화면·탭을 두지 않는다. 담는 순간 뜨는 **플로팅 Selection Bar가 장바구니 역할**을 한다 (PRD §14, §35-8/9).
담은 내용은 세션 동안 유지되어 다른 탭에 다녀와도 남아 있고, Bar는 수강신청 화면에서만 노출된다.
정원이 있는 반을 오래 담아두는 건 오히려 마감 위험이 있어, 서버에 저장하는 영속 장바구니는 넣지 않았다.

## 필터

필터 시트에서 **적용 전에 결과를 미리 보여준다**. 화면 아래 목록을 보러 내려가지 않아도 되고, 조건을 잘못 조합해 빈 화면을 만나는 일이 없다.

- 필터 항목은 **요일 · 수업 · 강사** 세 가지. 시간대는 두지 않는다 — 목록에 시간이 그대로 보이고, 구간을 나눠도 오전/오후로만 갈려 걸러지는 게 거의 없다
- 강사 순서는 원장님(소정T)이 먼저, 이후 가나다순 (`INSTRUCTORS`)
- 적용 버튼이 결과 수를 보여준다 — `수업 16개 보기`, 0건이면 비활성 (`filterCount()`)
- 결과가 0이 되는 옵션은 비활성 — 막다른 조합 자체를 만들 수 없다. 현재 선택된 값은 해제할 수 있도록 항상 활성
- 칩에는 개수를 적지 않는다. 숫자가 30개 가까이 흩어지면 조건을 고르는 일보다 숫자 읽기가 앞서게 된다
- 세는 단위는 모드에 따라 다르다 — 정규는 반(요일+시간), 보강·쿠폰은 수업 회차

## 화면의 역할 경계

같은 정보를 두 곳에서 관리하지 않는다.

| 화면 | 답하는 질문 |
|---|---|
| 홈 | 오늘 뭐가 있고 지금 뭘 해야 하지? |
| 내 수업 | 나는 언제 어떤 수업을 듣고 있지? — **시간표만** |
| 수강신청 | 뭘 신청할 수 있지? |
| 마이 | 내 등록·거래는 어떻게 돼 있지? |

내 수업은 시간표 하나만 다룬다. 등록한 정규반·금액·보강·쿠폰은 성격이 **계약과 거래**라 마이로 모았다.

```
마이
├ 수강 현황 — 정규반(취소·보강 포함) / 쿠폰
├ 결제     — 결제 내역
└ 설정     — 회원 정보 / 알림 설정
```

취소·보강은 **정규 수강권에 딸린 권리**이고 한도가 월 단위라, 별도 메뉴가 아니라
월별 정규반 카드 안에 넣는다. 그래야 8월·9월처럼 달이 여러 개일 때 어느 달의 잔여인지가 분명해진다.
(쿠폰 수업 취소는 보강이 아니라 쿠폰 1회 복구라 이 한도와 무관하다.)

메뉴에는 `주 4회`, `2회 남음`처럼 진입 힌트만 짧게 적고, 자세한 내용은 각 화면에서 본다.

## 반응형

| 폭 | 레이아웃 |
|---|---|
| ~767px | 모바일 — Bottom Navigation, 바텀시트, 전체 화면 플로우 |
| 768–1023px | 태블릿 — 같은 구조에서 폭만 720px로 확장 |
| 1024px~ | 데스크톱 — Bottom Navigation이 **좌측 레일**로, 홈은 2단, 수강신청 카드는 2열, 시트·플로우는 중앙 모달 |

전환은 전부 CSS 미디어쿼리로 처리하고 JS 분기는 없습니다. 홈의 2단은 `.deck`(모바일 `display:contents`) 래퍼만 씁니다.

## PRD와 다르게 간 부분

- **마이를 Bottom Navigation 4번째 탭으로 배치했습니다.** PRD §33은 3탭 + Header Profile 진입이지만, 제품 결정에 따라 탭으로 승격했습니다. Header의 Profile 아이콘은 제거했습니다.
- **알림은 노출하지 않습니다.** Header 벨 아이콘과 알림 화면을 뺐고, 마이의 `알림 설정`은 `준비 중`으로 둡니다. mock 데이터(`seed.notifications`)는 후속 작업을 위해 남겨뒀습니다.

## 용어 원칙

**보강과 쿠폰은 서로 다른 것**이라 이름도 분리합니다.

- **보강** — 정규 수강에 포함된 월 한도. `쿠폰`이라 부르지 않습니다
- **쿠폰** — 실제로 구매하는 회차권. 사용자에게도 `쿠폰`이 맞는 이름입니다

임시 명칭 `Class Hub / 클래스 허브`는 사용하지 않습니다.

## 운영 정책

확정된 정책과 **논의가 필요한 항목**은 별도 정책 문서에 따로 정리합니다.
확정 전 항목은 임의로 만들지 않고, 화면에서는 `* … 운영 정책 확정 후 안내됩니다` 각주로 표시합니다.

## 상태 확인용 스위치

**마이** 탭 → **프로토타입 상태 보기** 에서 로딩 / 불러오기 실패 / 신청 실패 화면을 확인할 수 있습니다. 실제 서비스에는 노출하지 않는 개발용 스위치입니다.
